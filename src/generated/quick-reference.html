01Surface

where you meet it

Terminal, IDE, desktop app, chat window. The front end — not the engine underneath.

one engine, several faces

02Harness

the program around the model

Assembles the context, calls the model, executes the tools the model asks for, and decides what happens next.

where the product lives
Prompt engineeringChange behaviour by changing what you send. No training involved.
Context engineeringWhat goes in the window, what gets dropped, what gets fetched again.
Retrieval (RAG)Fetch the document at question time so the answer rests on it.
Tool useThe model asks for a function. Your code decides whether to run it.
Approval modeWhich actions need a human before they land.

03Inference API

the call itself

Stateless HTTP. The whole conversation is re-sent every time, and the server keeps nothing between calls.

stateless

04Model

the trained artifact

An architecture plus learned weights, mapping input tokens to output token probabilities. No memory, no tools, cannot act.

a file, not a service
TokenThe unit it reads, emits, and is billed in. A word fragment, not a word.
Context windowA per-call ceiling on what it can attend to. Not a memory.
Agentic loop · repeat until done

Who is involved

Model provider — Trains it, owns the weights, sets the licence.

Model host — Runs someone else’s model and sells access.

What goes wrong

Hallucination — Confident, plausible, wrong — and indistinguishable from correct output, because truth is not a quantity the model computes.

How you know

Evaluation — A repeatable test. The only thing that turns “it seems better” into a claim someone else can check.

Almost everything people attribute to “the AI” — that it remembers, searches, runs code, asks permission — belongs to the harness, not the model.
